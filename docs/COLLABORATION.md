# 协作流程与分工

团队名称：**BLGNB**。

## 分工

| 角色 | 成员 | 主要职责 |
| --- | --- | --- |
| 前端 | 林俊晨（50%） | 页面、表单、收藏交互、导入导出界面 |
| 后端 | 陈子元（50%） | 数据存储、API、收藏逻辑、Excel 解析与生成 |

共同负责接口约定、前后端联调、验证、材料核对及共同博客内容。双方贡献比例各 50%，共同工作包含在各自比例中，合计 100%。

## 仓库协作

1. 仓库所有者在 Settings → Collaborators 中邀请队友，队友接受邀请。
2. 两人分别 Clone 仓库。
3. 开发前检查本地 `git config user.name` 和 `git config user.email`，确保关联本人账号。
4. 从最新 main 创建功能分支，例如 `feat/frontend-contacts`、`feat/backend-excel`。
5. 分阶段提交实际代码并 Push。
6. 创建指向 main 的 PR，说明功能和验证结果，互相检查后合并。
7. 下一阶段开始前同步 main。

需要在主分支保留各次提交时，可使用 Create a merge commit；Squash 会将 PR 中多个提交压成一次。

## 开始编码前约定

- 前后端语言、框架、运行环境及数据存储。
- 联系人字段与联系方式结构。
- 接口路径、请求响应、错误格式和开发端口。
- Excel 列名、多个联系方式的编码方式、重复导入处理规则。
- 将最终约定记录到项目文档。

## 提交记录

作业说明要求仓库 commit 次数至少 3 次，并统计每位贡献者的提交次数；每位成员都应参与编码。
建议两人各自按功能阶段提交，以清楚展示个人贡献。初始化文档不能证明业务功能已完成。

## Fork 注意事项

本仓库是新建仓库，并非 Fork。如果老师提供了指定起始仓库，应根据课程要求处理 Fork；不能将本仓库描述为已经完成 Fork。
