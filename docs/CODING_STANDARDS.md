# 代码规范

## 通用约定

- 文本统一使用 UTF-8，缩进与命名遵循所选语言及框架惯例。
- 确定技术栈后配置并记录格式化工具；避免同一模块混用风格。
- 命名表达实际用途，注释说明必要的业务原因和边界条件。
- 前后端接口字段、数据类型和错误格式先约定再实现。
- 对用户输入和导入文件进行校验，错误信息应便于用户理解。
- 不提交密码、令牌、真实联系人资料、本地数据库、依赖目录和构建缓存。
- 使用虚构数据完成演示。

## Git 提交

- 使用本人 Git 身份提交，每次提交对应一项可解释的实际工作。
- 推荐提交格式：`类型(范围): 简短说明`。
- 示例：`feat(frontend): add favorite contacts view`。
- 常用类型：`feat`、`fix`、`docs`、`refactor`、`test`、`chore`。
- 不为凑次数提交无意义改动，不代替另一位成员制造提交记录。

## 合并前检查

- 修改可以运行或构建，相关功能已验证。
- 涉及接口和 Excel 格式变化时，同步文档并完成联调。
- PR 写明改动、验证方法和仍存在的限制。
